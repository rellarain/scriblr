# HUI version 1: requirements

What the Helper UI must do to be complete for phase 1 (see the [roadmap](../roadmap.md)). HUI is a side interface: its mini form is in the band under the header, and its panel opens in the sidebar.

**Interview**: the phase 1 round is done (2026-11-26). The HUI round (the open questions below) comes before its mockup. HUI is built after VUI.

## The band

| Part | Today | Version 1 |
|---|---|---|
| Queue meter, chat heads, New chat, Outbox, Settings | built | as built |
| Work and break meters, Break button | only in AUI's band | also in HUI's band, for **everyone with helper time** |

## Consoles

| Console or tile | Today | Version 1 |
|---|---|---|
| Queue | built | as built |
| Chat › Conversation (responses, check in, hold, escalate, transfer, close), Help Tool (send a feature's guide), feedback drafts | built | as built |
| Chat › User | not built | **The user and their context**: their profile, their current project, book and word count, their earlier chats and their feedback |
| Outbox | built | as built |
| Settings › Workweek, Workday | not built | **Fold into UUI's Schedule** (one calendar of every role) |
| Settings (queue and chat settings) | built | as built |
| Inbox (Toning, Sorting, Explicating) | moved | in the Office's Desk, in AUI |
| **Dispatch** (new), for leads: managers, directors, channel support | not built | **Live helper status** (active, idle, inactive) by department and by queue; **moving helpers between queues**; **performance**. The Office's performance tabs show the same figures |

## Open questions (HUI round)

- What moving a helper does to their schedule.
- Whether a lead can take or hand over a waiting chat.
- How much of a writer's project a helper may see in Chat › User.
- Whether the queue meter's colour code in the plan (six shades for open and pending chats) is complete.
