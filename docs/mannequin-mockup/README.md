# Mannequin mockup (reference, not shipped)

The approved HTML mockup of the character design console and the art mannequin (a private Design artifact, version 13, 2026-11-08). It is the reference to port from for phases P1 to P7 of the plan; nothing here is loaded by the app.

- `designer-engine.js` is the pure engine (points and the four modes, bridges between parts, edge locks, shading layers, ranges, forms, colour, hair sections, tracing of the old hair, random previews). It is written so it ports 1:1 to TypeScript. P1 ports only the shape designer part (points, paths, symmetric outlines, templates, snapshots, limits, seeded random).
- `Main.dc.html` is the Designer (Configuration > Characters), `Editor.dc.html` the writer's editor inside the character card, `Palette.dc.html` the character palette, `Compare.dc.html`, `Review.dc.html` and `HairTrace.dc.html` the boards that compare the converted old drawing with the mannequin. They are Design canvas boards (`canvas.json` lists them).
- `exact-default.js` holds the exact shapes of the old portrait engine's default adult (every option of head, ears, eyes, brows, nose, mouth), generated by `export-exact.ts` (run with vite-node inside `frontend`, which imports the old engine). The per-character data (`exact-chars.js`) is generated from a user's own projects and is deliberately **not** kept here.
- `check-dc.js` is the smoke test used on the boards: it runs a board's logic against a stub, checks every `{{hole}}` resolves and calls every handler (`node check-dc.js <board> [tabs] [selections JSON]`; it requires `./project/designer-engine.js` and `./project/exact-default.js`, so copy the boards and these files into a `project/` folder first).

Decisions, limits and the interview behind it are in the plan file of the session that built it; the short version lives in the Characters design-system page.
