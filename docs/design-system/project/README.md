Scriblr is an offline desktop app for writing a book: outline it, draft it, read it back, revise it. This is the design system of its **Writer**: four stacked levels (Dash, Project, Outline, Draft), flat and square, coloured by the book and by the time of day.

It is **derived from the code**, not drawn beside it. `tokens.json`, `contrast.md`, the icon files and the component bundle are generated by `npm run design-system` (in `scriblr/frontend`) from the app's own theme and components, so what is written here is what the app does. Where a rule lives in the code is named on each page. The previews run the real app against a pretend project, with the app's labels and lorem ipsum for what is inside them.

## Content fundamentals

The app speaks in short labels and plain verbs. A control says what it does: **Write**, **Publish**, **Save**, **New chapter**, **Add chapter**, **Delete**. An empty area says what is missing and the one thing to do: "No notes yet. Add one to jot down a thought." "Nothing outlined yet. Add an arc or a chapter to begin." Counts are plain: "5 chapters · 47 words", "231 words of 3,000". Names are the writer's own terms (series, book, arc, chapter, act, scene, moment, plotpoint), never the system's. There are no exclamation marks and no emoji. [content-voice](content-voice.md) has the strings.

## Visual foundations

- **One palette, four times of day.** A user picks four hues (theme, accent, alert, admin accent). The zone (dawn, day, dusk, night) fixes saturation and starting lightness. Day and dawn are light with dark text; dusk and night are dark with white text. There is one ink per zone. [colour-zones](colour-zones.md).
- **Readable for every hue.** WCAG contrast, not a lightness rule: text is at least 4.5:1, icons and control edges 3:1. A colour's lightness is moved only as far as its hue needs. [contrast](contrast.md).
- **Flat and square.** Levels, tiles, tabs, cards and buttons have no radius, no gradients on panels and almost no shadow; depth is a step in colour. A level is a flat fill of its colour, and what sits inside steps one shade deeper each time, ending in light inputs. [spacing-shape-elevation](spacing-shape-elevation.md).
- **A colour is a hue, 0 to 360.** The project, each book, arc and chapter, and each plot category has one; saturation and lightness are the zone's. White text on every level. [level-colours](level-colours.md).
- **Chrome in sans, writing in serif.** System sans for everything you operate; Georgia for what you write and read (chapter titles, draft text, the preview, synopses). Small bold uppercase labels with letter-spacing mark sections. [typography](typography.md).
- **The page is paper.** In the Draft level and the preview the sheet is a light page with dark text by day and a dark page with light text at night, with the nested cards a step deeper each.
- **A book you can see.** The Outline is an open book: a cover, a stack of page edges, tabs for arcs and chapters, spines on a shelf that swivel into covers.

## Iconography

Line icons on a 24 grid, 1.8 stroke, round caps and joins, `currentColor`. 18px in the header tabs, 16 in buttons, 14 in tile titles. Reactions are six hearts, one glyph per level. [iconography](iconography.md); the files are in `assets/Icons`.

## Using it

- Take colours from `tokens.json` by name; in the app they are CSS variables set by `theme/tokens.ts` and re-derived inside a book (`.wrBookScope`). Do not hard-code white, black overlays or fixed lightness in new styles.
- The class names (`wr*`) are the app's own and are in `components/bundle.css`; the Writer's styles live in `frontend/src/assets/Interfaces/writer/writer.scss`.
- A new text-on-ground pair belongs in `frontend/src/theme/contrastAudit.ts`, so the test keeps it readable.
- This system describes the Writer. The older rounded tile grid and the helper and admin interfaces are not covered; where they differ, [known-drift](known-drift.md) says so.
