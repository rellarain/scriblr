# Known drift

Where the code does not yet follow the rules on the other pages. Each entry says what the code does, what the rule says, and the token to use. Nothing here is hidden: the app is described as it is, and this page is the list of what to fix next. (Items marked **fixed** were drift when this system was written and have been brought into line; they stay as a record of the rule.)

## Open

The app is described as it is; where a screen differs from the rules it is here or on the list above.

| What the code does | What the rule says | Fix |
|---|---|---|
| Page margins and indents are numbers (20, 22, 24, 26, 34, 56px: the page's padding, a nested card's indent, the Preview's paragraph indent), 1px adjustments and the sizes 14, 20 and 24px are not on a scale, and a few radii are not tokens (`50%`, 2px, a spine's 3px corner) | one scale, used by name | an indent step token that nested rows are a multiple of, and a page-margin token; the tests in `scripts/design-system/cssTokens.test.ts` show how |
| Text under the 11px floor outside the Writer, the helper and the admin screens: the sky toggle's date (9px, in a fixed-size widget), the Reader's footnote markers, badges and small print (10px), the Theme panel's timeline ticks and chip labels (9 to 10px), the autosave toggle's label | readable text, audited | raise them with the widgets that hold them, and add the test's files |

## Not covered by the audit

The audit lists text on its ground for the surfaces (also lifted by hover), the fills, the paper and its nested cards, the Preview page's two tones and its highlighted sentences, the reaction hearts, the edge tabs, the sky toggle, the Inbox's tones as marks, the plot category and subcategory surfaces, the Theme panel's timeline icons and the level panels. It does not yet include: a tone used as a bare fill beside a surface (a swatch, a bar: decoration beside a count), the helper and admin screens' own text beyond the surfaces they use, and a plotpoint's own text (it is fitted but is not in the table). Add a pair to `frontend/src/theme/contrastAudit.ts` when a new text-on-ground is made; the test then covers it for every hue.
